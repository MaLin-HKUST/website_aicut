# 08. 验收与回滚手册

本文回答什么问题：

- 本轮重建完成后必须验哪些内容
- 哪些情况视为验收失败
- 失败时如何回滚

## 1. A 机器验收

必须验证：

- 网站首页和登录页正常
- admin 正常
- SQLite 数据正常
- 网站业务 API 正常
- 调度 API 正常
- Scheduler Runtime 正常
- PostgreSQL 正常

## 2. Worker 侧验收

必须验证：

- Gateway 注册成功
- 心跳正常
- 可领取任务
- 可从 TOS 拉输入
- 可上传产物到 TOS
- 可写回状态

## 3. 主链路验收

至少跑通一条 Smart Cut 主链路：

1. 创建任务
2. 上传输入
3. analyze
4. preview
5. finalize
6. 前端查看结果

## 4. 失败路径验收

至少验证一条失败路径：

- Worker 异常
- 阶段失败
- 状态正确收口

## 5. 哪些情况必须回滚

以下情况属于必须回滚：

- 登录或 admin 不可用
- SQLite 数据异常
- 调度 API 不可用
- Scheduler 无法正常跑循环
- Worker 不能注册或不能领任务
- 主链路无法跑通
- 切流后出现无法快速定位的严重异常

## 6. 回滚顺序

回滚顺序应固定：

1. 识别上一个稳定锚点
2. 切回上一版前端/服务入口
3. 恢复上一版 release
4. 必要时恢复数据库到对应备份点
5. 重新跑最小健康检查

## 7. 回滚后的最低验证

至少验证：

- 登录
- admin
- `/auth/me`
- 调度健康
- 一条只读任务查看链路

## 对 Agent 的直接指令

- 没有验收，不要宣称重建完成。
- 没有回滚路径，不要开始不可逆清洗。
- 如果你无法准确说明“回滚到哪一版”，说明当前 release 管理仍然不合格。
