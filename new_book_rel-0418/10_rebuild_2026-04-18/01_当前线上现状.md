# 01. 当前线上现状

本文回答什么问题：

- 2026-04-18 这一天，A 机器当前真实存在什么运行面
- 为什么现在的线上状态不是目标架构
- 哪些目录、端口、容器在服务流量，哪些只是历史残留

## 1. 当前线上真实并存的三条线

### 1.1 旧主站线

当前仍存在：

- `website_aicut_api_1`
- 旧主站的 SQLite 数据目录
- `127.0.0.1:8000`
- `127.0.0.1:3000`
- `/home/malin/website_aicut`

它代表历史上的“网站主服务器整包线”。

### 1.2 rel0415 前端 slot 线

当前仍存在：

- `/home/malin/release_0415_slot`
- standalone Next runtime
- `192.168.92.197:3001`

目前正式域名 `xiaomajianji.cn` 的 nginx 入口实际上全部打到这条线。

### 1.3 新调度中心线

当前仍存在：

- `release0415_api`
- `release0415_scheduler`
- `release0415_worker`
- `pg-f10`
- `0.0.0.0:8001`
- `127.0.0.1:55432`

这条线承载了调度中心和一部分执行侧验证逻辑。

## 2. 当前端口事实

当前已确认的关键端口：

- `3000`：旧主站前端
- `3001`：rel0415 slot 前端 runtime
- `8000`：旧 SQLite/API 线
- `8001`：新调度 API 线
- `55432`：调度 PostgreSQL

这说明 A 机器当前不是“一套清晰主链路”，而是多条运行面并存。

## 3. 当前 nginx 事实

当前正式域名 `xiaomajianji.cn` 的 nginx 配置中：

- `/` -> `3001`
- `/_next/static/` -> `3001`
- `/api/proxy/` -> `3001/api/proxy/`

也就是说：

- 正式用户流量当前走的是 `release_0415_slot` 前端
- 而不是旧的 `3000` 网站前端

## 4. 当前数据库事实

### 4.1 SQLite

当前网站 SQLite 文件位于：

- `/home/malin/website_aicut/data/website_aicut.db`

它仍然是旧主站 admin/auth 的重要数据源。

### 4.2 PostgreSQL

当前调度 PostgreSQL 由 `pg-f10` 提供。

当前表包括：

- `scheduler_tasks`
- `smart_cut_devices`
- `smart_cut_edits`
- `smart_cut_tasks`

根据当前业务判断，这一批数据目前主要是联调与 mock 数据，不是必须保留的正式生产数据。

## 5. 当前目录事实

当前 A 机器上关键目录包括：

- `/home/malin/website_aicut`
- `/home/malin/release_0415_slot`
- `/home/malin/website_aicut_git`
- `/home/malin/website_aicut_repo.git`
- `/home/malin/website_aicut_f10_run`

这说明线上不仅运行面并存，代码和发布目录也并存。

## 6. 当前不符合目标架构的地方

按长期规则看，以下状态是错误或过渡状态：

- A 机器同时保留旧主站线和 rel0415 前端线
- A 机器上存在 Worker 相关运行面
- 发布流既有本地打包上传，也有云上 git/pull/build 尝试
- 同一台机器同时承载历史目录、当前目录、过渡目录

## 7. 当前现状的正确结论

当前线上不是“只有一个坏版本”，而是：

- 多条历史运行线叠加
- 多次局部修补
- 多套目录与脚本同时存在

这正是本轮需要重建，而不是继续打补丁的原因。

## 对 Agent 的直接指令

- 不要把当前线上目录结构误判成目标结构。
- 不要因为 `3001` 现在承接正式流量，就认为 `release_0415_slot` 是长期标准架构。
- 重建判断必须基于这里列出的真实现状，而不是基于旧汇报或单张截图。
