# 10. 重建执行清单

本文回答什么问题：

- 本轮重建应该按什么清单推进
- 每一步完成后要检查什么
- 哪些任务之间存在先后依赖

## 阶段 0：理解系统与专项文档

- [ ] 读完 `00_system_knowledge/`
- [ ] 读完 `10_rebuild_2026-04-18/`
- [ ] 明确 A 机器与 Worker 的职责边界
- [ ] 明确 SQLite 与 PostgreSQL 的职责边界

完成标准：

- 能准确说出哪类服务必须在 A 机器，哪类服务必须在 Worker

## 阶段 1：冻结当前线上状态

- [ ] 记录当前运行容器
- [ ] 记录当前关键镜像
- [ ] 记录当前关键端口
- [ ] 记录当前 nginx 配置
- [ ] 记录当前 SQLite 路径
- [ ] 记录当前 PostgreSQL 状态

完成标准：

- 有一份重建前快照

## 阶段 2：备份

- [ ] 备份 SQLite
- [ ] 备份 PostgreSQL
- [ ] 备份 release 信息
- [ ] 备份 nginx 与证书说明
- [ ] 上传远端备份到 TOS
- [ ] 校验 SHA256

完成标准：

- 本地与 TOS 各有可验证备份

## 阶段 3：定义目标运行面

- [ ] 明确 A 机器最终服务列表
- [ ] 明确 Worker 最终服务列表
- [ ] 明确前端正式入口
- [ ] 明确网站 API 与调度 API 边界
- [ ] 明确 TOS 作为跨机器数据交换层

完成标准：

- 目标拓扑图和运行面清单定稿

## 阶段 4：清理错误运行面

- [ ] 停掉无主测试容器
- [ ] 清理无主镜像
- [ ] 停掉不再需要的历史运行面
- [ ] 保留回滚锚点

完成标准：

- A 机器不再继续扩散历史运行面

## 阶段 5：重建 A 机器

- [ ] 重建网站主服务器
- [ ] 重建 SQLite 运行面
- [ ] 重建调度 API
- [ ] 重建 Scheduler Runtime
- [ ] 重建 PostgreSQL
- [ ] 重建正式前端
- [ ] 重建 nginx 路由

完成标准：

- A 机器能独立完成网站与调度中心职责

## 阶段 6：重建 Worker

- [ ] 部署 Worker Gateway 到 Worker 机器
- [ ] 部署 Smart Cut Worker 到 Worker 机器
- [ ] 验证 Gateway 与调度库连接
- [ ] 验证 TOS 输入输出

完成标准：

- Worker 侧正式接回

## 阶段 7：主链路验收

- [ ] 登录
- [ ] admin
- [ ] 创建任务
- [ ] analyze
- [ ] preview
- [ ] finalize
- [ ] 结果回流页面

完成标准：

- 至少一条主链路闭环成功

## 阶段 8：失败路径与回滚演练

- [ ] 失败路径验证
- [ ] 回滚路径验证
- [ ] 记录最终 release manifest

完成标准：

- 重建后的系统可运行且可回滚

## 对 Agent 的直接指令

- 没有完成前置阶段，不要进入下一个阶段。
- 每一个勾选项都应有对应证据：命令、日志、截图、manifest、备份记录。
