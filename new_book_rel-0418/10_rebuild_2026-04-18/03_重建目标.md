# 03. 重建目标

本文回答什么问题：

- 这次重建最终想把系统拉回什么状态
- A 机器和 Worker 机器分别要收敛成什么样
- 哪些当前线上运行面在重建后必须退出

## 1. 总目标

把当前混乱的线上形态，收敛回你定义的四段式分布式系统：

1. A 机器主服务器
2. A 机器调度中心
3. Worker Gateway
4. Smart Cut Worker

同时把发布、备份、回滚流程标准化。

## 2. A 机器重建后的目标状态

### 2.1 A 机器主服务器

保留：

- 网站前端
- 网站业务 API
- SQLite
- admin/auth

### 2.2 A 机器调度中心

保留：

- 调度 API
- Scheduler Runtime
- PostgreSQL

### 2.3 A 机器不再承载的内容

退出：

- Worker Gateway 正式运行面
- Smart Cut Worker 正式运行面
- 多套前端长期并存
- 多套历史主站并存

## 3. Worker 机器重建后的目标状态

保留：

- Worker Gateway
- Smart Cut Worker
- 必要的执行环境

不保留：

- A 机器网站主服务
- A 机器调度中心逻辑

## 4. TOS 在重建后的目标角色

TOS 要成为：

- 业务输入输出层
- 跨机器数据交换层
- 备份归档层

不再继续把：

- A 机器本地临时目录
- Worker 本地工作目录

当成跨机器数据真相。

## 5. 数据目标

### SQLite

目标：

- 保留 admin 和网站主数据

### PostgreSQL

目标：

- 作为调度中心正式真相库

当前库里的 mock 数据可在重建时清空重建。

## 6. 发布目标

目标发布方式：

- 本地开发与测试
- Git 记录正式版本
- 云上拉代码
- 云上构建
- 云上备份
- 云上切流

## 7. 备份目标

目标备份方式：

- 本地最近 3 天
- TOS 长期保留
- 数据库、release、镜像三层备份

## 对 Agent 的直接指令

- 如果你的方案不能把系统收敛成这里描述的状态，那它不是本轮重建方案。
- 不要把当前线上还能跑的历史运行面当成必须保留的未来形态。
