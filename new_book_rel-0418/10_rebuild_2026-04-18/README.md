# 10_rebuild_2026-04-18

本文回答什么问题：

- 为什么 2026-04-18 要开启 A 机器重建专项
- 哪些 Agent 需要读这一层
- 本层文档和长期规则层是什么关系

## 本层定位

这一层不是长期架构规则书，而是本轮重建专项手册。

它专门回答：

- 当前线上现状到底是什么
- 为什么会乱
- 本轮重建准备怎么做
- A 机器与 Worker 要如何收口
- 本轮如何发布、如何备份、如何验收、如何回滚

## 适用对象

以下 Agent 必须阅读本层：

- 参与 A 机器重建的 Agent
- 参与 Worker 侧迁移或收口的 Agent
- 参与发布、备份、回滚脚本重构的 Agent

以下 Agent 不必默认阅读本层：

- 只做普通页面功能开发的 Agent
- 只做局部业务逻辑开发的 Agent

## 与真实数据专项的关系

本层只负责说明：

- 系统是如何从混乱状态被拉回当前可运行状态的
- 当前正式运行面是什么
- 当前 release、热补、回滚锚点是什么

如果后续 Agent 的任务已经变成：

- 用真实样本跑 Smart Cut
- 生成真实任务证据
- 补齐真实数据链路文档
- 推进热补收口与发布收口

则不应继续只停留在本层，而应转到：

- [../20_real_data_chain_2026-04-19/README.md](../20_real_data_chain_2026-04-19/README.md)

## 与长期规则层的关系

- `00_system_knowledge/` 描述的是长期正确架构
- 本层描述的是“当前为什么偏离了长期正确架构，以及如何拉回去”

不能反过来理解：

- 不能把当前脏状态当成长期规则
- 不能因为当前线上有某个目录或端口，就认定那是未来标准形态

## 对 Agent 的直接指令

- 参与本轮重建前，先读长期规则层，再读本层。
- 做任何清洗、停服务、删目录、删镜像动作前，必须先确认本层的备份与回滚手册。
- 参与实际执行时，不要跳过 `基础网络信息和账号信息.md`。
- `10_重建执行清单.md` 现在是执行 runbook，不再只是阶段标题。
- 如果你只想快速理解“当前线上正在跑的版本”，不要从 `01_当前线上现状.md` 开始倒推，先读 `11` 和 `12`。
- 如果你已经确认当前线上运行面稳定，下一步要做真实数据业务闭环，请切到 `20_real_data_chain_2026-04-19/`。
