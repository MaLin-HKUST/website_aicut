# 08. 前端协作总览

本文回答什么问题：

- 前端相关协作规则有哪些长期有效的入口
- 什么时候该看前端上线 runbook，什么时候该直接复制交付模板
- 前端任务开始前必须知道哪些系统信息和文档

## 1. 适用场景

这组文档适用于：

- 登录页、欢迎页、TTS、Smart Cut、任务列表等用户端页面改版
- admin 界面样式调整
- 单页或多页视觉统一
- 布局、配色、间距、文案、模块排序、交互细节优化

不适用于：

- 架构重建
- 调度中心
- Worker 算法
- 数据库迁移

## 4. 前端任务的硬规则

### 7.1 一次只做一组强相关页面

推荐：

- 一次只做 `/login`
- 或一次只做 `/tts`
- 或一次只做 `/smart-cut + /tasks`

不推荐：

- 一次同时大改所有用户端页面

### 7.2 必须给“当前图 + 目标图”

只给目标图，不给当前图，前端 agent 容易误判偏差。

### 7.3 必须写清边界

如果你不写清：

- 能不能改文案
- 能不能改交互
- 能不能改布局
- 能不能动真实数据链路

那前端 agent 很容易越界。

### 7.4 不要只说“改好了”

如果前端 agent 只回：

- “改好了”

但没有 branch / commit SHA / 改动文件列表 / 实际运行过的验证命令，主集成人无法安全接手。

### 7.5 缺少 4 个核心字段就视为未交付

以下 4 项是硬门槛：

- branch
- commit SHA
- 改动文件列表
- 实际运行过的验证命令

缺少任一项，主集成人应直接退回，不进入集成阶段。

## 5. 具体执行入口

- 要做前端上线、截图、Playwright 验收、线上发布：
  - 读 [09_前端页面修改上线Runbook.md](./09_前端页面修改上线Runbook.md)
- 要直接发任务给前端 coding agent，或者要求他按固定格式交回：
  - 复制 [10_前端CodingAgent交付纯模板.md](./10_前端CodingAgent交付纯模板.md)

## 6. 对 Agent 的直接指令

- 如果你是前端 coding agent，先确认任务只涉及 UI 还是涉及交互边界。
- 如果你是主集成人，缺少 `branch / commit SHA / 改动文件列表 / 验证命令` 任一项时，不要假设“对方已经改好了可直接合”。
- 如果页面与真实任务链有关，合并前必须额外确认不会影响 `login / welcome / tts / smart-cut / tasks` 的正式链路。
