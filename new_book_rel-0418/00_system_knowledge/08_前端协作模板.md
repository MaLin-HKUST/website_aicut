# 08. 前端协作模板

本文回答什么问题：

- 当你想把页面截图交给前端 coding agent 修改时，应该怎么下任务
- 前端 coding agent 改完后，应该怎样把结果交回主集成人
- 前端任务开始前必须知道哪些系统信息和文档

## 1. 适用场景

这份模板适用于：

- 登录页、欢迎页、TTS、Smart Cut、任务列表等用户端页面改版
- admin 界面样式调整
- 单页或多页视觉统一
- 布局、配色、间距、文案、模块排序、交互细节优化

不适用于：

- 架构重建
- 调度中心
- Worker 算法
- 数据库迁移

## 3. 你发给前端 coding agent 的任务模板

你可以直接复制下面模板，把中括号内容替换掉：

```markdown
# 前端任务

## 页面范围
- 路由: [例如 /tts]
- 页面名称: [例如 TTS 工作台]

## 当前问题
- 我不满意的地方:
  - [例如 配色太灰]
  - [例如 左侧栏太宽]
  - [例如 模块位置不对]

## 目标参考
- 目标截图:
  - [截图 1 路径或图片]
  - [截图 2 路径或图片]
- 当前截图:
  - [当前页面截图]

## 必须保持不变的边界
- 不改接口
- 不改数据库
- 不改调度逻辑
- 不改 Worker 逻辑
- [如果允许改文案/交互，写清楚；不允许也写清楚]

## 需要你完成的事
1. 按目标截图修改页面视觉和布局
2. 保持现有业务功能可用
3. 给出修改前后截图
4. 给出 git 分支和 commit
5. 给出验证方法

## 交付格式
- 页面:
  - [路由]
- 改动文件:
  - [文件列表]
- git:
  - branch: [分支名]
  - commit: [commit SHA]
- 验证:
  - [build/test/截图]
- 剩余偏差:
  - [哪些地方还没完全做到]
```

## 4. 前端 coding agent 改完后，必须怎么交回

前端 coding agent 交回时，必须给主集成人这些信息：

### A. 代码定位信息

- 仓库路径
- branch 名
- commit SHA

### B. 修改范围

- 改了哪些页面
- 改了哪些文件
- 哪些地方只是视觉改动
- 哪些地方顺带改了交互或文案

### C. 验证信息

- 本地 build 是否通过
- 本地截图或录屏
- 如果有 Playwright/测试，也要写明

### D. 风险与剩余偏差

- 哪些地方只是近似还原
- 哪些页面还没改到位
- 是否可能影响当前真实链路

## 5. 前端 coding agent 交回模板

前端 coding agent 应按这个格式交回：

```markdown
## 前端交付

### 页面
- [例如 /tts]

### 目标参考
- [参考图说明]

### 改动文件
- [apps/web/app/tts/page.tsx]
- [apps/web/components/navigation/user-workspace-shell.tsx]

### git
- branch: [feature/...]
- commit: [abcdef1]

### 验证
- build: [pass/fail]
- 截图:
  - [修改后截图路径]
- 其他:
  - [如果跑了 Playwright 或人工验证]

### 剩余偏差
- [例如 左侧导航和参考图还有 10% 差异]
- [例如 下载区文案还没细调]

### 风险
- [例如 只改了 UI，没有回归真实任务链]
```

## 6. 主集成人拿到后应该怎么处理

主集成人收到前端 agent 的交付后，应按这个顺序处理：

1. 看 branch 和 commit 是否明确
2. 看修改范围是否越界
3. 看是否碰到了真实链路相关页面
4. 看 build/截图是否足够说明结果
5. 决定：
   - 直接 cherry-pick / 合并
   - 手工整合
   - 只参考设计，不直接合

## 7. 前端任务的硬规则

### 7.1 一次只做一组强相关页面

推荐：

- 一次只做 `/login`
- 或一次只做 `/tts`
- 或一次只做 `/smart-cut + /tasks`

不推荐：

- 一次同时大改所有用户端页面

### 7.2 必须给“当前图 + 目标图”

只给目标图，不给当前图，前端 agent 容易误判偏差。

### 7.3 必须写清边界

如果你不写清：

- 能不能改文案
- 能不能改交互
- 能不能改布局
- 能不能动真实数据链路

那前端 agent 很容易越界。

### 7.4 不要只说“改好了”

如果前端 agent 只回：

- “改好了”

但没有 branch / commit / 截图 / 改动范围，主集成人无法安全接手。

## 8. 对 Agent 的直接指令

- 如果你是前端 coding agent，先确认任务只涉及 UI 还是涉及交互边界。
- 如果你是主集成人，没有 branch 和 commit 时不要假设“对方已经改好了可直接合”。
- 如果页面与真实任务链有关，合并前必须额外确认不会影响 `login / welcome / tts / smart-cut / tasks` 的正式链路。
