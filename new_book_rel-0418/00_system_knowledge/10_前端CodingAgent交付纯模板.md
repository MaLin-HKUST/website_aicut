# 10. 前端 Coding Agent 交付纯模板

本文不是解释文档，只提供可直接复制的模板。

使用规则：

- 你要发任务给前端 coding agent：复制“模板 A”
- 前端 coding agent 改完回交：复制“模板 B”
- 任一必填项缺失，视为未完成交付

## 必填项说明

### 1. `branch`

含义：

- 本次修改所在分支

规则：

- 必须能直接切换到该分支
- 不能只写“当前工作区”或“本地改好了”

### 2. `commit SHA`

含义：

- 可定位本次修改的完整提交

规则：

- 必须能 `git show <commit>`
- 不能只给短描述
- 不能只给基线 commit，不给本次修改 commit

### 3. `改动文件列表`

含义：

- 本次真正修改过的文件清单

规则：

- 必须逐条列出
- 不能只写“改了前端”
- 不能混入无关文件

### 4. `实际运行过的验证命令`

含义：

- 你真的在本地跑过的验证

规则：

- 必须写命令本身
- 必须写结果
- 不能只写“已验证”

### 5. `截图`

含义：

- 页面真实效果证据

规则：

- 至少给修改后截图
- 最好给修改前后对照
- 没有截图时，应明确说明原因

### 6. `剩余偏差`

含义：

- 还没完全达到参考图的地方

规则：

- 不能默认写“无”
- 若有近似还原，应明确指出

### 7. `风险`

含义：

- 本次改动的已知不确定性

规则：

- 如果没有回归真实链路，要写明
- 如果只做了 UI 没做 build，要写明

---

## 不合格交付示例

以下任一情况都视为不合格：

- 只说“改好了”
- 没有 `branch`
- 没有 `commit SHA`
- 没有改动文件列表
- 没有实际运行过的验证命令
- 没有截图，却声称“效果已经对了”

---

## 对前端 coding agent 的直接指令

- 你必须按模板 B 原样回复，不要自由发挥成一段散文。
- 你如果没有新的 `commit SHA`，就不应宣称这是一份可集成的最终交付。
- 你如果没有跑验证命令，就应明确写“未验证”，不要伪装成已验证。
