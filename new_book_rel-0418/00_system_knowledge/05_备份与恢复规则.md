# 05. 备份与恢复规则

本文回答什么问题：

- SQLite 和 PostgreSQL 应该如何备份
- 本地与 TOS 各保留什么
- 代码、release、镜像该如何备份
- 恢复演练应该怎么做

## 1. 总原则

- 数据库备份、代码备份、镜像备份不是一回事
- Git 是代码主真相
- 数据库备份负责恢复状态
- 镜像备份负责加速恢复，不是唯一恢复手段
- 本地保留最近 3 天，长期留存在 TOS

## 2. SQLite 备份规则

适用对象：

- A 机器网站主服务器的 SQLite

建议：

- 每天至少一次全量备份
- 每次正式发布前强制备份
- 重大数据库修改前强制备份

保留策略：

- 本地：最近 3 天
- TOS：日备 7 天，周备 4 周，月备 6 个月

备份内容：

- 数据库文件本体
- SHA256
- manifest
- 恢复命令示例

## 3. PostgreSQL 备份规则

适用对象：

- A 机器调度中心 PostgreSQL

建议：

- 每天逻辑备份
- 每周一次完整归档检查
- 每次正式发布前强制备份

保留策略：

- 本地：最近 3 天
- TOS：日备 7 天，周备 4 周，月备 6 个月

备份内容：

- `pg_dump` 导出文件
- SHA256
- manifest
- 恢复命令示例

## 4. release 备份规则

每次正式 release 必须保留：

- git sha
- git tag 或 release id
- compose 文件或启动脚本版本
- env 模板
- nginx 相关配置版本
- 发布验收结果

这些内容应打成 release bundle，并上传 TOS。

## 5. 镜像备份规则

镜像采用分层策略：

- 正式 release 镜像归档到 TOS
- 临时测试镜像不做长期归档
- 无 tag 镜像不归档

正式归档镜像应包含：

- component
- tag
- digest
- git sha
- archive sha256
- manifest

## 6. TOS 存储层规则

建议：

- 备份和业务产物分开 prefix 或分开 bucket
- 备份对象默认只写不改
- 配置生命周期自动清理旧版本

推荐前缀：

- `backup/a-machine/sqlite/`
- `backup/a-machine/postgres/`
- `backup/a-machine/releases/`
- `backup/a-machine/images/`
- `backup/worker-01/releases/`
- `backup/worker-01/images/`

## 7. 恢复规则

恢复必须遵守：

- 先选恢复点
- 先在隔离环境验证
- 再恢复正式环境

恢复顺序通常是：

1. 代码与 release 信息
2. 镜像或运行时
3. 数据库
4. 服务启动
5. 验收

## 8. 恢复演练要求

至少每月做一次演练，验证：

- SQLite 备份可恢复
- PostgreSQL 备份可恢复
- release bundle 可复盘
- 正式 release 镜像可导入
- A 机器最小主链路可恢复

没有演练过的备份，不应被视为有效灾备体系。

## 对 Agent 的直接指令

- 不要把“镜像还在”误当成“系统可恢复”。
- 做任何重建、清洗、迁移前，先确认数据库备份和 release 备份都存在。
- 如果你新增了发布流程但没有新增备份与恢复说明，这个流程是不完整的。
