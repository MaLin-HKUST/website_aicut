# 01. 系统定义

本文回答什么问题：

- `website_aicut` 到底是什么系统
- 为什么它不是普通网站
- 四大组成分别是什么
- SQLite、PostgreSQL、TOS 在系统中分别承担什么角色

## 1. 项目本质

`website_aicut` 不是内容展示站，而是一个分布式任务处理系统。

它的最小业务闭环是：

1. 用户在网站创建任务
2. 用户上传输入数据
3. A 机器接收任务并写入调度体系
4. Worker 侧异步执行长任务
5. 产物上传到 TOS
6. 前端回看状态与结果

这意味着：

- 网站只是用户入口，不是全部系统
- 任务处理是异步的，不是页面内同步完成
- 数据需要跨机器传递
- 执行链路必须脱离 A 机器主服务器

## 2. 四大组成

### 2.1 A 机器主服务器

A 机器主服务器负责对用户交付：

- 网站前端
- 网站业务 API
- 用户登录、认证、admin
- 企业、用户、素材等管理能力
- 支撑网站运行的 SQLite

这是用户眼中的“网站本体”。

### 2.2 A 机器调度中心

A 机器还承担调度中心：

- 调度 API
- 调度 Runtime
- 调度数据库 PostgreSQL

它的职责不是直接跑算法，而是：

- 接住来自网站的任务
- 把任务变成调度任务
- 选择 Worker
- 推进状态机

### 2.3 Worker Gateway

Worker Gateway 运行在 Worker 机器上，不应该常驻 A 机器。

它负责：

- 监听调度库中的可执行任务
- 维护设备注册与心跳
- 从 TOS 下载输入
- 调用算法镜像
- 将结果上传回 TOS
- 把执行状态写回调度中心

### 2.4 Smart Cut Worker

Smart Cut Worker 是纯算法执行镜像。

它只负责：

- 读取输入数据
- 生成中间数据或结果数据
- 输出处理产物

它不负责：

- 调度
- 心跳
- 设备注册
- TOS 读写编排

## 3. 三类核心基础设施

### 3.1 SQLite

SQLite 只服务网站主服务器侧。

它承载：

- admin
- 登录认证
- 企业/用户/素材等网站管理数据

SQLite 不应该成为调度真相库。

### 3.2 PostgreSQL

PostgreSQL 只服务调度中心。

它承载：

- 调度任务
- 设备状态
- Smart Cut 阶段状态
- 编辑稿与执行相关状态

PostgreSQL 不应该承载 admin 或网站管理数据。

### 3.3 TOS

TOS 是跨机器数据交换层和持久产物层。

它负责：

- 输入文件上传
- Worker 拉取输入
- Worker 上传中间产物和最终产物
- A 机器与 Worker 之间的数据解耦
- 备份和归档的远端存储

TOS 不只是业务产物层，后续也用于备份层。

## 4. 当前重点业务能力

当前重点能力是 Smart Cut 粗剪。

阶段模型：

- `analyze`
- `preview`
- `finalize`

它们共同体现了这个系统的真实形态：

- 网站负责发起
- 调度中心负责编排
- Worker 负责执行
- TOS 负责传输与持久化

## 5. 设计判断标准

如果一个改动会导致：

- Worker 常驻 A 机器
- 算法镜像直接碰调度逻辑
- SQLite 开始承载调度状态
- PostgreSQL 开始承载 admin 数据
- 跨机器数据依赖本地目录而不是 TOS

那这个改动就是错误方向。

## 对 Agent 的直接指令

- 先把项目理解为“分布式任务处理系统”，再看页面、接口、容器和数据库。
- 不要因为用户先看到的是网站，就把整个系统误判成单机 Web 应用。
- 之后所有关于部署、重建、发布、备份的判断，都必须服从这里定义的四段式架构。
