# 02. 系统架构与职责边界

本文回答什么问题：

- A 机器和 Worker 机器分别应该承载什么
- 哪些服务必须留在 A 机器
- 哪些服务必须离开 A 机器
- 网站链路、调度链路、执行链路如何分开

## 1. A 机器的职责

A 机器承担两层角色，但都属于中心侧：

### 1.1 网站主服务器

应包含：

- 正式网站前端
- 网站业务 API
- admin
- auth
- SQLite

这部分面向用户和运营管理。

### 1.2 调度中心

应包含：

- 调度 API
- 调度 Runtime
- PostgreSQL

这部分面向任务编排和设备管理。

## 2. Worker 机器的职责

Worker 机器承担执行侧：

- Worker Gateway
- Smart Cut Worker
- 运行算法所需的本地执行环境

Worker 的正确角色是“执行节点”，不是“中心节点”。

## 3. 三条链路

### 3.1 网站链路

组成：

- 用户页面
- 登录
- admin
- 网站任务入口
- SQLite

特点：

- 面向人
- 数据量相对小
- 更关注认证、页面和基础业务管理

### 3.2 调度链路

组成：

- 调度 API
- Scheduler Runtime
- PostgreSQL

特点：

- 面向任务状态机
- 面向设备调度
- 不直接做算法处理

### 3.3 执行链路

组成：

- Worker Gateway
- Smart Cut Worker
- TOS 输入输出

特点：

- 面向长任务
- 面向文件与产物
- 面向异步执行

## 4. 数据边界

### 4.1 SQLite 只做网站侧真相

应该写入：

- 用户
- 企业
- 素材管理
- admin 相关状态
- 网站会话

不应该写入：

- 调度任务真相
- Worker 设备状态
- 长任务阶段状态

### 4.2 PostgreSQL 只做调度侧真相

应该写入：

- SchedulerTask
- SmartCutTask
- SmartCutEdit
- SmartCutDevice

不应该写入：

- admin 管理实体
- 网站主会话
- 仅用于页面呈现的后台配置项

### 4.3 TOS 是跨机器数据真相层之一

应该保存：

- 输入视频
- 输入文案
- 中间产物
- 最终产物
- 备份归档

不应该继续长期依赖：

- A 机器本地临时目录作为跨机器数据交换方式
- Worker 本地目录作为唯一产物持久化位置

## 5. 错误架构信号

如果线上出现以下情况，说明系统正在走偏：

- A 机器同时承担网站、调度、Gateway、算法执行
- Worker 直接读 A 机器本地目录而不是 TOS
- 前端长期同时挂多套正式运行面
- 一个页面链路同时依赖 SQLite 和 PostgreSQL 作为同一种状态真相
- agent 说不清某个服务到底是网站侧、调度侧还是执行侧

## 6. 未来扩展原则

当系统扩展到多个 Worker 时：

- A 机器仍只做中心侧
- Worker 只做执行侧
- 扩容靠增加 Worker 节点，而不是把更多执行逻辑塞回 A 机器
- 所有跨机器输入输出都应继续走 TOS

## 对 Agent 的直接指令

- 在改代码前先判断：这段逻辑属于网站、调度，还是执行侧。
- 如果你打算把 Worker Gateway 或 Smart Cut Worker 部署在 A 机器长期运行，请先停止，这违反系统边界。
- 如果你发现一个改动让 SQLite 和 PostgreSQL 的职责变得模糊，请先回到这里重新判断。
