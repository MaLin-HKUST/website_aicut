# 03. 代码结构映射

本文回答什么问题：

- 当前仓库里的主要路径分别对应系统中的哪个角色
- 哪些目录属于网站侧
- 哪些目录属于调度中心
- 哪些目录属于 Worker 侧

## 1. 网站侧

### `apps/web`

对应角色：

- A 机器主服务器中的网站前端

负责：

- 登录页
- 用户侧页面
- admin 页面
- 调用 `/api/proxy/*`

注意：

- `apps/web` 是用户入口，不是调度器
- 前端可以调用调度 API，但不应拥有调度状态真相

### `apps/api/main.py`

对应角色：

- A 机器的网站业务 API 入口

负责：

- 网站业务侧接口
- auth/admin
- 与 SQLite 侧业务逻辑衔接

注意：

- 这个入口位于 A 机器中心侧，不是 Worker 侧入口

## 2. 调度中心

### `apps/scheduler/main.py`

对应角色：

- A 机器调度 Runtime 入口

负责：

- 启动调度循环
- 读取调度数据库
- 驱动任务分配

### `apps/scheduler/scheduler_service.py`

对应角色：

- 调度核心

负责：

- 调度策略
- 设备选择
- 状态推进

### `apps/models/scheduler_task.py`

对应角色：

- 调度任务模型

### `apps/models/device.py`

对应角色：

- Worker 设备状态模型

### `apps/models/task.py`

对应角色：

- 业务任务模型
- 与 Smart Cut 阶段状态相关

## 3. Worker 侧

### `worker/main.py`

对应角色：

- Worker Gateway 入口

### `worker/core.py`

对应角色：

- Worker Gateway 核心循环

负责：

- 注册
- 心跳
- 领取任务
- 调处理器

### `worker/processors/*.py`

对应角色：

- Worker 侧任务处理器

它们负责：

- analyze
- preview
- finalize

注意：

- 这些处理器属于执行链路，不属于 A 机器主服务器

## 4. TOS 适配

### `apps/services/tos_service.py`

对应角色：

- TOS 访问层

支持：

- Fake TOS
- Real TOS

它是跨机器数据交换与备份归档的基础组件之一。

## 5. 文档与脚本

### `scripts/rel0415/*`

对应角色：

- 当前一批发布与上线脚本

注意：

- 这些脚本中包含历史遗留和过渡方案
- 未来要逐步收敛到统一发布流，不能把它们全部当成长期标准

### `book/*`

对应角色：

- 历史文档

注意：

- 只作参考
- 不再作为唯一权威入口

## 6. 当前代码路径与未来运行面的对应关系

- `apps/web` -> A 机器网站前端
- `apps/api` -> A 机器网站业务 API 与调度 API 的代码来源
- `apps/scheduler` -> A 机器调度中心
- `worker/` -> Worker 机器执行侧
- `apps/services/tos_service.py` -> A 与 Worker 共用的对象存储访问基础

## 对 Agent 的直接指令

- 做代码修改前，先在这里定位这段代码属于哪条链路。
- 不要因为代码都在一个仓库里，就误以为所有服务都应该部署在一台机器。
- 如果你修改的是 `worker/`，默认假设你的目标部署位置是 Worker 机器，不是 A 机器。
