# 前端工作台与任务列表重构

## 页面目标

前端不再扮演“草稿真相源”。

前端只做两件事：

- 驱动显式用户动作
- 渲染主任务和 run timeline 的后端真相

## `/smart-cut` 工作台

## 默认空态

用户进入 `/smart-cut` 时：

- 默认展示空工作台
- 不自动创建任务
- 不自动恢复隐藏草稿

页面主按钮：
- `开启任务`

## 开启任务后

一旦创建主任务：

- 左上展示主任务标题/状态
- 上传区绑定当前 `task_id`
- 页面进入任务工作态

## Upload 区

行为改为：

- 选择视频
- 选择文案
- 上传完成后前端只调用 `upload-complete`
- 然后自动进入 analyzing 展示

前端不再长期卡在“本地上传进度条是真相”模式。

## Analyze 阶段

analyze 由后端自动触发。

页面展示：
- analyzing 进度
- 主任务卡同步变化

Analyze 成功后：
- 展示删除线脚本
- 展示 `audio_a`
- 解锁：
  - `开始生成试听`
  - `开始生成视频`

## Preview 阶段

Preview 是循环行为：

- 用户可多次改删除线
- 每次点试听都创建一次新的 preview run

失败时：
- 页面提示“上一轮试听失败”
- 不锁死工作台
- 允许继续重试

## Finalize 阶段

用户可以：

1. 直接基于 analyze 结果点击 `开始生成视频`
2. 或基于最新 preview 结果点击 `开始生成视频`

点击 finalize 后：
- 当前工作台退出该任务
- 页面回到空态
- 任务列表承接后续进度

## 任务列表

## 列表展示对象

任务列表只展示 **主任务卡**。

不展示：
- 每次 preview 试听卡
- 每次 finalize 派单卡

## 卡片动作

每张主任务卡至少提供：

- `继续处理`
- `编辑任务`
- `放弃任务`
- 如果已完成：`下载结果`

## 详情区域

任务详情区展示：

- 基本信息
- 输入文件
- 当前成功版本
- run timeline
- 最近错误
- 历史 preview/finalize 版本

## 继续处理 vs 编辑任务

### 继续处理

用于未完成任务：
- 回到该任务工作台继续当前流程

### 编辑任务

用于已完成或未完成任务：
- 在同一主任务下继续修改
- 产生新 edit version / 新 run 记录
- 不覆盖旧结果

## 放弃任务

页面需要有：

- 明确的 `放弃任务` 按钮
- 二次确认弹窗

点完后：
- 任务进入 `abandoned`
- 工作台退出该任务

## 与当前旧逻辑的关键差异

不再保留：

- `draft/current` 自动恢复
- `session_scope_id` 草稿归属
- 页面本地缓存作为主任务来源
- `preview` 完成后才允许 finalize 的硬前置

## 活跃影响面

重构不只覆盖 `/smart-cut` 页面，还必须覆盖这些活跃文件：

- `apps/web/components/navigation/use-user-workspace-data.ts`
- `apps/web/lib/task-center.ts`
- `apps/web/components/task-center/task-center-shell.tsx`
- `apps/web/components/navigation/user-workspace-shell.tsx`
- 未来新的 `apps/web/components/smart-cut/*`

否则会再次出现：
- 任务列表和工作台显示不同真相
