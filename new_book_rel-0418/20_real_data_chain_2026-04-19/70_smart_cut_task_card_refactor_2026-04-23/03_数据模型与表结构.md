# 数据模型与表结构

## 目标

把当前 Smart Cut 的数据模型从：

- 1 张隐藏草稿主表
- 若干状态字段
- 部分 scheduler 关联

重构成：

- 1 张主任务表
- 1 张子执行表
- 1 张编辑版本表

## 表结构方案

## 1. `smart_cut_tasks`

继续使用现有 `smart_cut_tasks`，但语义重定义为：

- 用户能在任务列表中看到的主任务卡

### 保留字段

- `id`
- `user_id`
- `status`
- `current_stage`
- `task_title`
- `created_at`
- `updated_at`
- `original_video_url`
- `reference_text_url`
- `analyze_script`
- `asr_result_tos_key`
- `active_edit_id`
- `final_video_url`
- `groundtruth_url`

### 新增字段

- `company_id`
  - 主任务公司级可见性
- `current_run_id`
  - 当前活跃 run
- `latest_successful_run_id`
  - 最近成功执行的 run
- `failed_stage`
  - 最近一次失败发生在哪个 run type
- `abandoned_at`
  - 放弃时间
- `revision_count`
  - 已创建的编辑版本数

### 删除或退役语义

- `visible_in_task_center`
  - 退役
  - 主任务从创建开始就可见，不再用它控制隐藏/显示
- `session_scope_id`
  - 退役
  - 新模型不再依赖 session 恢复草稿

## 2. 新表 `smart_cut_task_runs`

新增子执行表，记录每一次实际运行。

### 字段

- `id`
- `task_id`
- `run_type`
  - `upload | analyze | preview | finalize`
- `status`
  - `created | queued | running | success | failed | abandoned`
- `sequence_number`
- `scheduler_task_id`
- `source_edit_id`
- `payload_snapshot`
- `result_snapshot`
- `error_message`
- `created_at`
- `started_at`
- `completed_at`
- `updated_at`

### 设计意图

- upload 即使不走 scheduler，也要有 run 记录
- analyze / preview / finalize 都通过 run 与 scheduler 关联
- timeline 不再从主任务状态反推，而是直接展示 run 历史

## 3. `smart_cut_edits`

继续使用现有 `smart_cut_edits`，但语义收敛为“编辑版本表”。

### 关键字段

- `id`
- `task_id`
- `version_number`
- `edited_script`
- `status`
- `audio_a_url`
- `audio_b_url`
- `delay_cuts_tos_key`
- `pause_cuts_tos_key`
- `created_at`
- `updated_at`

### 新的关系

- 每次 preview 或重新编辑都可以产生新 edit
- `smart_cut_task_runs.source_edit_id` 指向发起该次运行所基于的 edit
- `smart_cut_tasks.active_edit_id` 指向当前用户看到的最新活跃 edit

## 4. `scheduler_tasks`

继续作为底层调度表，不替代主任务表。

### 角色

- 只记录可调度执行的任务
- 不承担产品可见任务卡语义

### 关系

- `smart_cut_task_runs.scheduler_task_id -> scheduler_tasks.id`
- 不再让前端直接把 `scheduler_tasks` 当成任务中心真相

## 可见性规则

### 主任务可见性

- 按 `company_id` 共享
- 同公司账号能看到同一批主任务卡
- 不同公司严格隔离

### 编辑版本和子执行

- 不在任务列表平铺成独立卡片
- 仅在任务详情 timeline / 历史区域展示

## 生命周期规则

### abandoned 清理

- 主任务进入 `abandoned` 后保留 7 天
- 7 天后可清理：
  - `smart_cut_task_runs`
  - `smart_cut_edits`
  - TOS 中间产物

### success 保留

- 已成功任务不走 7 天清理
- 保留任务卡、版本历史、最终产物链接

## 数据迁移原则

- 当前 PG 中 Smart Cut 数据可视为测试/过渡数据
- 允许进行结构性重塑
- 旧隐藏草稿不做兼容恢复
- 新模型上线前应清理旧 Smart Cut 主任务数据
