# 产品模型与状态机

## 产品模型

新的 Smart Cut 采用：

- 1 个主任务
- 多个编辑版本
- 多个子执行记录

### 主任务

主任务是用户在任务列表里看到的唯一任务卡。

主任务从用户点击 `开启任务` 开始创建。

它负责承载：
- 上传输入
- analyze 结果
- preview 循环
- finalize 产物
- 放弃/继续处理/编辑动作

### 编辑版本

编辑版本承载：
- 删除线后的 `edited_script`
- `audio_a / audio_b`
- delay cuts / pause cuts

规则：
- 每次 preview 或重新编辑都可以产生新版本
- 已完成任务再次编辑，不覆盖旧版本，只追加新版本

### 子执行记录

子执行记录承载：
- upload
- analyze
- preview
- finalize

每次执行都形成一条 run 记录，供任务详情 timeline 展示。

## 用户动作

### 1. 开启任务

用户进入 `/smart-cut` 默认看到空工作台。

只有点击 `开启任务` 时，系统才创建主任务。

### 2. 继续处理

用户从任务列表进入未完成任务后，可以继续：
- 查看当前状态
- 上传剩余输入
- 等待 analyze
- 做 preview
- 直接 finalize

### 3. 编辑任务

用户可以对已完成或未完成任务继续编辑。

实现语义：
- 不是覆盖旧结果
- 而是在同一主任务下生成新编辑版本和新执行记录

### 4. 放弃任务

用户显式点击 `放弃任务` 后：
- 主任务进入 `abandoned`
- 当前工作台退出该任务
- 未开始的后续执行不再继续
- 已有历史执行记录保留

## 主任务状态机

### 主状态

- `waiting_start`
  - 只存在于前端空工作台，不落库
- `waiting_upload`
- `uploading`
- `analyzing`
- `waiting_user`
- `finalizing`
- `success`
- `abandoned`

### 主状态说明

- `waiting_upload`
  - 已创建主任务，但还没完成输入
- `uploading`
  - 输入文件正在进入任务
- `analyzing`
  - upload 已完成，系统自动开始 analyze
- `waiting_user`
  - analyze 或 preview 已完成，轮到用户继续操作
- `finalizing`
  - 正在生成最终视频
- `success`
  - 当前主任务至少已有一个成功 finalize 结果
- `abandoned`
  - 用户显式放弃

### 不再作为主任务状态的内容

以下不再出现在主任务状态里：

- `ready_analyze`
- `previewing`
- `preview_failed`
- `finalize_failed`
- `analyze_failed`

这些都应转移到 **run 层** 记录。

## 子执行状态机

### run 类型

- `upload`
- `analyze`
- `preview`
- `finalize`

### run 状态

- `created`
- `queued`
- `running`
- `success`
- `failed`
- `abandoned`

### run 失败语义

如果某次 preview 失败：
- 主任务仍回到 `waiting_user`
- preview failure 只记录在该条 run 上
- 用户可以直接再次点试听

如果某次 finalize 失败：
- 主任务回到 `waiting_user`
- finalize failure 只记录在该条 run 上
- 用户可以继续调整或重新提交生成视频

## 关键交互规则

### Upload

- 上传完成后自动触发 analyze
- 用户不需要再点一次 analyze

### Preview

- preview 是可选动作，不是强制动作
- 用户可以：
  - 改删除线再试听
  - 或直接跳过 preview，基于 analyze 结果生成视频

### Finalize

finalize 有两条合法路径：

1. analyze -> finalize
2. analyze -> preview(可多次) -> finalize

### 关闭浏览器 / 刷新 / 重新登录

- 不自动放弃主任务
- 主任务继续存在
- 用户可通过任务列表重新进入

### 退出登录

- 只结束登录态
- 不自动放弃主任务

### 真正终止任务

只有显式点击 `放弃任务` 才终止主任务。
