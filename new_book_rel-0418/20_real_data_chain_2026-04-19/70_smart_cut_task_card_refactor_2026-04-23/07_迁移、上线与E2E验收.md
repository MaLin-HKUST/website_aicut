# 迁移、上线与 E2E 验收

## 迁移原则

这次重构不是在旧隐藏草稿模型上继续兼容性修补，而是：

- 关闭旧入口
- 备份
- 明确旧模型退役
- 上线显式主任务卡模型

## 数据处理原则

### PostgreSQL

当前 Smart Cut 相关 PG 数据可视为过渡/测试数据。

上线前允许：
- 清理旧 `smart_cut_tasks`
- 清理旧 `smart_cut_edits`
- 清理旧 `scheduler_tasks` 中的 Smart Cut 派单记录

### TOS

保留：
- 备份对象
- 已完成任务最终视频

允许清理：
- 旧隐藏草稿相关中间产物
- abandoned 7 天后的中间产物

## 上线顺序

### Phase 0：文档与模型冻结

- `70_*` 作为唯一执行主包冻结
- `50_*` 降级为历史参考
- L00 备份与下线记录确认完整

### Phase 1：数据库与后端模型

- 新增 `company_id`
- 新增 `smart_cut_task_runs`
- 调整主任务状态语义
- 退役 draft/current 逻辑

### Phase 2：调度单一真相

- API、scheduler、worker 全部围绕主任务 + run
- 不再允许只有一侧认识的 ghost task

### Phase 3：前端工作台

- 空态 + `开启任务`
- upload 自动 analyze
- analyze-only finalize
- 任务列表主卡 + timeline

### Phase 4：live E2E

只在上述 3 层都收口后，再恢复 `/smart-cut` 入口。

## 验收场景

### E2E-01

`start -> upload -> auto-analyze`

通过标准：
- 用户点 `开启任务`
- 上传完成后系统自动 analyze
- 页面出现脚本和 `audio_a`
- 任务列表能看到该主任务卡

### E2E-02

`analyze-only finalize`

通过标准：
- analyze 完成后不做 preview
- 直接点 `开始生成视频`
- 主任务进入任务列表运行
- 工作台回空态
- 最终视频可下载

### E2E-03

`preview loop -> finalize`

通过标准：
- 用户可多次试听
- preview 失败后可重试
- 最新版本成功后可 finalize
- 任务最终成功

### E2E-04

`编辑已完成任务`

通过标准：
- 已完成任务可再次进入编辑
- 新预览/新 finalize 作为同一主任务下的新版本
- 旧结果仍可追踪

### E2E-05

`放弃任务`

通过标准：
- 用户点 `放弃任务`
- 主任务变为 `abandoned`
- 工作台退出当前任务
- 后续不会再恢复该任务为活动任务

### E2E-06

`公司级可见性`

通过标准：
- 同公司账号可见同一主任务卡
- 不同公司账号互不可见

## 回滚原则

如果新模型上线失败：

- 使用 `06_上线前备份与下线动作.md` 中记录的 runtime/source/quarantine 备份
- 恢复 A 机旧 runtime
- 恢复旧 Smart Cut 前端源码
- 必要时从 TOS 备份回滚前端实现

## 注意事项

- 在单一真相修好前，不要重新开放 `/smart-cut`
- 不要一边保留旧隐藏草稿入口，一边上线新主任务卡入口
- 只允许一种产品模型同时在线
