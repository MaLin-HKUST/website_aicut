# 05_证据清单与产物目录

本文回答什么问题：

- 本专项的证据应该放在哪里
- 每一步至少要保存哪些文件
- 后续 Agent 应该如何快速定位这轮真实数据运行结果

## 目录规则

本专项的证据固定放在：

- `new_book_rel-0418/20_real_data_chain_2026-04-19/artifacts/`

每一次真实数据运行新建一个时间戳目录，例如：

- `artifacts/20260419_153000_real_data_run/`

## 每次运行至少应保存的文件

### 请求与状态文件

- `create.json`
- `upload.json`
- `analyze.json`
- `analyze_complete.json`
- `preview.json`
- `preview_complete.json`
- `finalize.json`
- `final_success.json`

### 执行辅助文件

- `task_id.txt`
- `scheduler_task_ids.txt`
- `active_edit_id.txt`
- `sample_info.txt`
- `api_base.txt`
- `nginx_upstream.txt`

### Worker 与 TOS 证据

- `worker_logs.txt`
- `tos_objects.txt`
- `download_check.txt`

### 最终总结

- `summary.md`

## summary.md 至少应包含的字段

- 执行时间
- operator / agent
- 样本视频路径
- 样本文案路径
- 业务任务 ID
- analyze 调度任务 ID
- preview 调度任务 ID
- finalize 调度任务 ID
- active edit ID
- 最终 `final_video_url`
- 最终 TOS key
- 当前 nginx upstream
- 当前 Worker 名称
- `ffprobe` 状态
- 热补状态
- 结论：pass / blocked / degraded

## 证据判断标准

### 通过

必须有：

- 新任务 ID
- analyze / preview / finalize 完整状态文件
- Worker 日志摘要
- TOS 对象证据
- 最终总结

### 不完整

以下情况都视为证据不完整：

- 只保存终态，没有过程文件
- 没保存 Worker 侧证据
- 没保存 TOS 对象证据
- 没记录使用的真实样本路径

## 与其他目录的关系

本专项的 artifacts 只记录：

- 真实数据正式链路联调
- 真实数据验收
- 真实数据后的热补收口回归

不要把下列内容混进这里：

- 2026-04-18 重建战役证据
- A 机器重建前快照
- 预重建备份锚点
- 与本专项无关的页面改版证据

这些内容继续留在：

- `10_rebuild_2026-04-18/rebuild-artifacts/`

## 对 Agent 的直接指令

- 每次真实数据运行都新建独立 artifacts 目录。
- 不允许覆盖上一次真实数据运行的证据。
- 如果一次运行失败，也必须留下失败证据，不允许只保留成功那次。
