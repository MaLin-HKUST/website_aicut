# 01_目标与完成标准

本文回答什么问题：

- 本专项到底要完成什么
- 什么叫“真实数据链路已经跑通”
- 什么状态还不能算完成

## 目标

本专项的直接目标是：

- 在**当前正式运行面**上，用**真实视频 + 真实参考文案**跑通 Smart Cut 全链路
- 证明 Worker 处理的是真实输入，不是 mock 数据或临时生成的小样本
- 把这轮真实数据结果写回当前项目文档，形成后续 Agent 可复用的单一真相

## 当前正式运行面的含义

本专项中的“当前正式运行面”固定指：

- 正式域名：`xiaomajianji.cn`
- nginx upstream：`127.0.0.1:3301`
- A 机器：
  - host web on `127.0.0.1:3301`
  - `website_aicut_api_1` on `127.0.0.1:8000`
  - `a-machine-phase5-api` on `18001`
  - `a-machine-phase5-postgres` on `55433`
  - `a-machine-phase5-scheduler`
- Worker：
  - `worker1-phase6-gateway`

## 真实数据链路的完成标准

必须同时满足以下条件，才算“真实数据链路完成”：

1. 本轮创建了新的业务任务
- 任务 ID 必须是本轮新生成的
- 不能复用 phase 7 的旧任务 ID

2. 输入样本必须是真实样本
- 视频来自：
  - `/Volumes/XIAOMA-A-1T/wei_videodb/C2384_reencoded.mp4`
- 参考文案来自：
  - `/Volumes/XIAOMA-A-1T/wei_videodb/ref.txt`

3. 上传链路真实可用
- `upload-direct` 成功，或
- 在它失败时，通过 `upload-prepare -> 直传 TOS -> upload-complete` 成功

4. analyze 成功
- 业务任务进入：
  - `status = waiting_user`
  - `current_stage = user_select`
- TOS 中存在 analyze 产物：
  - `asr.json`
  - `script.json`
  - `delay_cuts.json`
  - `audio_a.mp3`

5. preview 成功
- 任务再次回到：
  - `status = waiting_user`
  - `current_stage = user_select`
- 生成新的 `active_edit_id`
- TOS 中存在 preview 音频产物

6. finalize 成功
- 任务进入：
  - `status = success`
  - `current_stage = complete`
- `final_video_url` 有值
- TOS 中存在最终视频对象

7. Worker 侧证据成立
- Worker 日志里必须能对应到本轮新任务
- 不能只看 A 机器任务状态就宣布成功

8. 证据已落档
- 本层 `artifacts/` 中必须存在：
  - 任务创建结果
  - 上传结果
  - analyze / preview / finalize 结果
  - Worker 日志摘要
  - TOS 对象清单
  - 最终总结

## 还不能算完成的状态

以下情况不算完成：

1. 只是页面能打开
2. 只是 API 返回 200
3. 只是 analyze 成功
4. 只是任务进入了 previewing / finalizing 但没有最终 `success`
5. 只是数据库状态改了，但 TOS 没有对应产物
6. 只是 Worker 跑了日志，但业务任务没有完成
7. 结果没有落档到 `new_book_rel-0418/`

## 次级目标

在真实数据链路跑通之后，本专项还要为后续工作准备好：

- 当前线上热补事实的准确记录
- 下一轮“热补收口到标准发布”的清晰边界
- Worker finalize 环境缺 `ffprobe` 这一问题的明确定位和处理优先级

## 对 Agent 的直接指令

- 不要把“phase 7 已跑通假样本”当成“真实数据链路已完成”。
- 不要在没有 Worker 证据和 TOS 证据的情况下宣布通过。
- 如果真实数据闭环没跑通，不要提前进入热补收口。
