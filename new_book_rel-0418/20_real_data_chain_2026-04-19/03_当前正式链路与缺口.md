已知热补：

- `apps/services/tos_service.py`
- `apps/api/routes/tasks.py`
- `apps/scheduler/scheduler_service.py`

这意味着：

- 当前链路功能上可用
- 但发布真相仍不完全等于“git checkout + 标准构建 + 标准部署”

### 2. Worker Gateway 仍不是纯净镜像

已知事实：

- Worker Gateway 当前启动时会先 `pip install tos`
- 这不是长期可接受的正式运行方式

## 为什么现在必须做真实数据联调

原因很直接：

1. 现在系统已经不是“完全不可用”的紧急状态
2. 现在最关键的问题从“能不能跑”变成了“哪一段已经真实通过，哪一段还靠人工收口”
3. 如果不把真实样本闭环补上，后续任何 Agent 都会把 phase 7 的假样本成功误判成真实业务成功

## 当前专项的边界

本层只负责回答：

- 用真实样本把正式链路跑通
- 留下真实证据
- 写清当前还剩哪些收口项

本层不直接等同于：

- 发布系统重构
- 镜像系统重构
- Worker 全环境完善
- 原始大文件压力测试

这些属于下一阶段或后续专项。
