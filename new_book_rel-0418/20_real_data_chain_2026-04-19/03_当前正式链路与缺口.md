- 当前正式链路已经做到哪里
- 当前还缺哪几步，为什么还不能算最终完成
- 真实数据联调为什么现在是必要的

- `10_rebuild_2026-04-18/12_2026-04-19_当前Release与证据索引.md`
- `10_rebuild_2026-04-18/rebuild-artifacts/20260419_phase7_happy_path/happy_path_evidence.md`

## 当前还没有完成的部分

### 1. phase 7 用的不是本专项要求的真实样本

当前 `scripts/rebuild_phase7/a_machine_candidate_happy_path.sh` 中，视频输入是：

- 临时生成的 `source_video.mp4`

文案输入也是脚本内联的短文本，不是：

- `/Volumes/XIAOMA-A-1T/wei_videodb/ref.txt`

这意味着：

- phase 7 证明的是“当前链路可以跑通”
- 但它还没有证明“当前正式链路已经能处理你指定的真实视频和真实参考文案”

### 2. 当前线上仍有热补

已知热补：

- `apps/services/tos_service.py`
- `apps/api/routes/tasks.py`

这意味着：

- 当前链路功能上可用
- 但发布真相仍不完全等于“git checkout + 标准构建 + 标准部署”

### 3. Worker finalize 环境不完整

已知问题：

- Worker finalize 仍缺 `ffprobe`

这意味着：

- finalize 当前能成功
- 但会走保底码率路径
- 这不一定会阻塞“链路通过”
- 但会阻塞“执行环境完全达标”的结论

## 为什么现在必须做真实数据联调

原因很直接：

1. 现在系统已经不是“完全不可用”的紧急状态
2. 现在最关键的问题从“能不能跑”变成了“能不能用真实数据稳定地跑”
3. 如果不把真实样本闭环补上，后续任何 Agent 都会把 phase 7 的假样本成功误判成真实业务成功

## 当前专项的边界

本层只负责回答：

- 用真实样本把正式链路跑通
- 留下真实证据
- 写清当前还剩哪些收口项

本层不直接等同于：

- 发布系统重构
- 镜像系统重构
- Worker 全环境完善
- 原始大文件压力测试

这些属于下一阶段或后续专项。

## 当前最关键的缺口列表

1. 正式链路真实样本闭环尚未落证
2. 真实任务的 Worker 日志与 TOS 产物尚未形成新证据包
3. 热补未进入标准构建
4. Worker `ffprobe` 未补齐

## 对 Agent 的直接指令

- 不要把 phase 7 的成功直接宣传成“真实数据成功”。
- 先补真实样本闭环，再进入热补收口和环境补齐。
