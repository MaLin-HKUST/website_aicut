# 02_数据模型与接口重构

## 数据模型

本轮重构不新增独立草稿表，直接在现有 `smart_cut_tasks` 上补字段。

建议新增字段：

- `visible_in_task_center: bool`
  - 含义：这个任务是否应出现在任务中心
  - 默认：`false`
- `session_scope_id: str | null`
  - 含义：当前登录会话的服务端作用域 ID
  - 用于恢复当前会话的唯一活动草稿

## 字段语义

### visible_in_task_center

- `false`
  - upload / analyze / preview 阶段的隐藏草稿
- `true`
  - 点击 `开始生成视频` 后正式进入任务中心的任务

### session_scope_id

- 同一用户、同一登录会话共享同一个 `session_scope_id`
- 同一用户同一 `session_scope_id` 只允许一条未完成草稿
- logout 后新登录必须得到新的 `session_scope_id`

## 接口重构

### 保留但语义改变

- `POST /api/smart-cut/tasks`
  - 变成底层“创建隐藏草稿任务”的能力
  - 不再作为页面一进入就调用的入口

### 建议新增

- `GET /api/smart-cut/draft/current`
  - 返回当前用户当前会话的活动草稿
  - 若没有活动草稿，返回空

- `POST /api/smart-cut/draft/current/ensure`
  - 在用户开始上传或开始分析前，确保当前会话存在草稿
  - 若已存在，则返回现有草稿
  - 若不存在，则创建新的隐藏草稿并返回

### finalize 时必须保证的事务

`start_finalize` 必须在同一事务内完成：

1. 写入北京时间任务标题
2. `visible_in_task_center = true`
3. 推进状态为 `finalizing`
4. 创建 finalize 调度任务

## 历史数据处理

新增字段后，需要做一次性回填：

- 历史中间态任务默认隐藏：
  - `waiting_upload`
  - `ready_analyze`
  - `analyzing`
  - `waiting_user`
  - `previewing`
  - `preview_failed`
  - `analyze_failed`
- 历史正式任务默认保留可见：
  - `finalizing`
  - `finalize_failed`
  - `success`
- 如存在歧义，以“是否已经进入最终输出链”为准
