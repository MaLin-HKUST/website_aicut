# 50_smart_cut_workspace_refactor_2026-04-21

本文回答什么问题：

- Smart Cut 工作台为什么需要重构，而不是继续在现有交互上打补丁
- 这次重构的目标交互、任务边界、数据边界和任务中心可见性规则是什么
- 开发应该如何拆解、并行、验证和记录进度

## 本专项定位

这个目录是 `20_real_data_chain_2026-04-19/` 下的一个**重大交互重构专项包**。

它不负责：

- 重写整个调度中心
- 重写整个 Worker 协议
- 重新定义 Smart Cut 算法

它只负责一件事：

- 把当前 `/smart-cut` 从“进入即建空任务 + 后台任务主导页面”的实现，改成“同一登录会话草稿驱动页面 + finalize 才进入任务中心”的交互模型

## 已锁定的产品决策

这些决策已经确定，执行者不需要再自行判断：

- Smart Cut 是**一个会话草稿的四段生命周期**：
  - `upload`
  - `analyze`
  - `preview`
  - `finalize`
- 同一用户、同一登录会话内，最多只有 **1 个活动草稿**
- 用户切页、刷新、关标签后再打开，只要仍在同一登录会话内，草稿状态必须恢复
- 用户退出登录后，下次重新登录视为新会话，不恢复旧草稿
- analyze 完成后，页面内立即显示：
  - 删除线文本
  - `audio_a` 首版音频
- preview 完成后，页面内继续显示：
  - 用户修改过删除线后的 `audio_b`
- 只有点击 `开始生成视频` 时，这个草稿才进入任务中心
- 任务中心任务名统一为：
  - `智能剪气口-YYYYMMDD-HHMMSS`
- 时间统一使用北京时间
