## 执行原则

1. 真实浏览器必须是 headed 模式，不允许只跑 headless。
2. 执行顺序固定按 `task.json.tasks` 从上到下。
3. 每一步都要同时看：
   - 页面端反馈
   - 后端接口
   - 调度数据库
   - Worker
   - TOS
4. 任何一步失败，都先记录，不允许直接绕过。
5. 本专项的目标是发现真实问题，不是“尽快把整条链跑完”。

## 对 Agent 的直接指令

- 不要自行减少检查项；页面能点通，不代表专项通过。
- 不要用 API 直调替代浏览器动作，除非 `task.json` 明确写的是后端侧验证步骤。
- 不要把失败判定成“环境偶发问题”然后继续后面的步骤；先按 `failure_capture` 落证据。
- 如果页面端和后端状态不一致，以后端接口、调度数据库和 Worker 日志三者的交集为准，再把差异写入本轮总结。
