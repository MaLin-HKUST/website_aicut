## 3. 真正的出错点

核心出错逻辑在：

- [script_to_delay_cuts.py:321](/Users/malin13/Documents/trae_projects/aicut2602/libs/cut_breakpoints/src/script_to_delay_cuts.py:321) `_find_time_by_content()`
- [script_to_delay_cuts.py:219](/Users/malin13/Documents/trae_projects/aicut2602/libs/cut_breakpoints/src/script_to_delay_cuts.py:219) `_convert_to_delay_cuts()`

### 具体过程

#### `_find_time_by_content()`

做的事：

1. 取出当前删除片段文本
2. 在当前任务 ASR 拼出来的完整文本里搜索
3. 找不到时，尝试 `_fuzzy_search()`
4. 还找不到时，它现在返回：

```python
return max(0, search_start), 0.0, 0.0
```

对应代码：

- [script_to_delay_cuts.py:379-381](/Users/malin13/Documents/trae_projects/aicut2602/libs/cut_breakpoints/src/script_to_delay_cuts.py:379)

#### `_convert_to_delay_cuts()`

拿到上面的返回值后继续做：

```python
duration = end_time - start_time
```

因为 `start_time == 0.0`，`end_time == 0.0`，所以：

- `duration == 0`

于是触发：

```python
if duration <= 0:
    raise ValueError(f"DelayCut 定位失败：片段时长非正数: {marked_content!r}")
```

对应代码：

- [script_to_delay_cuts.py:262-263](/Users/malin13/Documents/trae_projects/aicut2602/libs/cut_breakpoints/src/script_to_delay_cuts.py:262)

## 4. 为什么这个报错不够好

当前实际的第一性错误是：

- “这段删除文本在当前任务的 ASR 里没找到”

但最终抛出来的错误却是：

- “片段时长非正数”

这会导致：

1. 调试者误以为是时间换算或边界问题
2. 看不出是输入文本 mismatch
3. 看不出是哪一个删除片段第一次找不到

所以即使不改匹配算法本身，**也应该先改报错语义**。
