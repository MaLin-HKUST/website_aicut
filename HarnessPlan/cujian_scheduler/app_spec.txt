目标
- 将 Smart Cut 三阶段流程接入 scheduler，形成可派工、可恢复、可验收的调度系统。
- 使用 Harness 模式管理该专项，保证跨 session 可恢复、可持续推进。
- 建立自动化规则层、Fake TOS 集成层、真实 TOS 上线验收层三层验证。

核心能力
- 业务任务层与调度任务层分离。
- analyze / preview / finalize 作为三种独立调度任务。
- 前端直传 TOS，后端通过 upload-complete 绑定输入。
- Worker 从 TOS 下载输入到 /data/smart-cut/{task_id}/，处理后上传结果。
- preview 可重复执行，finalize 只读取最后一次成功 preview。
- 支持跨 Worker 接续。

固定约束
- 真实 worker 镜像路径：/Volumes/XIAOMA-A-1T/docker_hub/play_gound/website_aicut-smart_cut_worker_latest.tar.gz
- Fake TOS 根目录：/Volumes/XIAOMA-A-1T/docker_hub/FakeTos
- Fake TOS 容器内挂载路径：/fake-tos
- Fake TOS 只用于集成回归，不用于最终上线验收。
- 测试结束后必须清理 Fake TOS run_id 目录和 worker 本地 /data/smart-cut/{task_id}。

成功标准
- Harness artifact 完整，可通过 init.sh status / repo-check / cleanup 检查。
- feature_list.json 明确记录阶段性 backlog。
- case_catalog.yaml 覆盖真实数据验收清单中的全部 case id。
- release gate runner 能按 auto / fake_tos / real_tos 三种模式出报告。
- Harness 留下可执行的清理脚本与配置模板，后续实现可直接沿 backlog 推进。
