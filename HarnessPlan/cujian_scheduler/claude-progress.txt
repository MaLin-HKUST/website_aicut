## F04 安全修复记录（Code Review 后）

### 修复的安全问题

1. **High**: 回调接口完全裸露
   - 修复：新增 `apps/api/app/worker_auth.py` Worker 身份验证模块
   - 回调接口现在要求必须提供 `scheduler_task_id` 和 `worker_id`
   - 验证：
     - 调度任务 ID 必须匹配业务任务的 `last_scheduler_task_id`
     - Worker 必须是被分配执行该任务的 Worker
     - Worker 状态必须是 running/post/error
     - Worker 心跳不能超时（5分钟）

2. **High**: 回调没有和具体调度任务/执行节点建立关联
   - 修复：回调接口现在要求 `scheduler_task_id` 和 `worker_id` 参数
   - `verify_callback_matches_scheduler_task()`: 验证调度任务匹配
   - `authenticate_worker_callback()`: 验证 Worker 身份和任务分配
   - 防止：stale callback、重复回调、错 worker 回调

3. **Medium**: start_analyze_stage() 先提交再派工，非原子性
   - 修复：使用事务包裹调度任务创建和业务状态更新
   - `dispatch_tick()` 在事务提交后调用，失败不影响已创建的任务
   - 添加异常处理和回滚

4. **Medium**: 测试未覆盖回调安全问题
   - 新增测试：
     - `test_analyze_callback_missing_params`: 缺少参数拒绝
     - `test_analyze_callback_wrong_scheduler_task`: 错误调度任务 ID 拒绝
     - `test_analyze_callback_wrong_worker`: 错误 Worker ID 拒绝
