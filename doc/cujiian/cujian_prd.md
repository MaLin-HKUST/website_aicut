现在新增了一个 CLI 选项：

  行为是：

  - 先调用 libs/incoming_video_process
  - 把归一化后的视频保存到输出目录
  - 文件名是 *_normalized_input.mp4
  - 同时保存一份处理记录 *_normalized_input.process.json

  python libs/cut_breakpoints/src/run_raw_cut.py \
    -i /path/to/input.mov \
    -r /path/to/reference.txt \
    -o ./output \
    --normalize-input-video \
    --cut-video

## 需求描述：
所以我们在这里需要把这个代码分成两个阶段，第一个阶段呢，就是我们在处理这个step a的时候，
会输出一个叫script.txt的文件，那这个文件呢，我们在输出的时候是用大括号括住所有要删除的信息，
那么这个时候放在前端呢，我们需要用删除线的格式来表述，那么用户会看到我们运行结束script，
然后改成了删除线显示在前端页面，然后用户可以通过前端页面跟这个跟这个script去做互动，
它可以修改这些删除线的位置，当它修改好了，它可以点击生成语音。
然后我们就会生成一段音频，这个音频就是step. A的音频，然后用的是用户修改过的script，
这里提醒用户在前端是用删除线的，而我们后端的代码是用大括号的，所以这里需要转一次，
就是把删除线转大括号，然后这样我的程序就不用修改就可以继续执行了。所以后端和前端需要有删除线转大括号，
大括号转删除线这两个程序，并且我做完step b之后也是音频，然后我们把这一段也剪了气口之后的音频给用户去听，
那用户如果觉得听了以后没问题了，他去点生成视频，
在这期间，他都可以跟这个文档互动，然后来完成这个剪辑的动作。这个就是我们的智能剪气口功能

### 二次修订增加的功能。
在右边增加一列功能[在生成视频按钮的上面，加入]，这个功能可以让用户去勾选。输出视频规格：  []1080P竖屏， []原始尺寸
他选择输出的视频是否保持原视频尺寸。他勾选，那么我们就不做输入视频的normalize，然后就用它的原视频去做剪辑。如果选了 []1080P竖屏。 那么我们对他做归一化。 这个归一化应该是生成视频之前去做。 如果1080P，那么输出的码率，控制在 min(输入码率, 和12Mbps) 

### 三次修订增加的功能。
1. 上传视频，是在前端页面端上传到TOS
2. 新加入下载视频，也就是生成视频结束之后，就生成一个下载的文字带超链接。用户可以点击下载。
3. 这个下载的超链接也来自于TOS，生成视频所生成出的视频要上传TOS服务器。然后传回下载链接。

### 四次修订增加的功能。
其实用户修改过的preview的文档，其实是一个GroundTruth。我们需要在文本框边上放一个勾选框。叫做，[]投喂本文案给AI ，默认是勾着的
这里我们要针对每个公司，建立他们的数据库，也就是每一个Pair的数据我们都记录。 
这个记录的地方就是用户点击了生成视频。点击之后，我们就做这个记录。 用户的每一个案例里面，他的：标准文案，输入的视频，输入视频的ASR，我们输出的script，用户修改后的script。
这些文字记录在一个位置，然后进行保存。（保存在TOS的一个专属路径 cujian_input_data/{company}/{year-month}/cujian_userdata_{timestampe}）
