# Smart Cut 调度系统真实数据上线验收测试用例清单

## 1. 文档目标

本文档定义 Smart Cut 调度系统在接入真实 `smart_cut_worker`、真实 TOS、真实素材后，用于上线前阻断的最终验收测试清单。

目标不是“做一遍演示”，而是建立一套明确的上线门槛，使以下问题在上线前被发现：

- 调度状态机错误
- 分步骤任务无法正确释放/重派 Worker
- TOS 上传绑定错误
- 跨步骤产物丢失
- Worker 本地成功但对象存储失败
- 恢复、放弃、超时逻辑错误
- 真实素材在容器内路径、依赖、性能不满足要求

## 2. 适用范围

本清单适用于以下改造后的系统：

- `smart_cut` 作为业务任务
- `smart_cut_analyze` / `smart_cut_preview` / `smart_cut_finalize` 作为调度任务
- 前端直传 TOS，后端以 `upload-complete` 绑定输入
- Worker 从 TOS 下载输入到 `/data/smart-cut/{task_id}/`
- analyze / preview / finalize 分阶段派工
- 每一步完成后可释放 Worker
- preview 可重复执行
- finalize 基于最后一次成功 preview

## 3. 上线通过标准

本版本建议按以下标准作为发布阻断门槛：

1. 全部单元/集成/Fake TOS 自动化测试通过
2. 本文档中的全部 `P0` 与全部 `P1` 真实数据测试通过
3. 所有关键对象存储断言通过
4. 所有关键状态路径断言通过
5. 所有失败场景均能产生正确的失败状态或报警
6. 至少完成一次“换 Worker 恢复”和一次“TOS 上传失败”演练

说明：
- 没有任何测试能从数学上保证“线上绝对零问题”
- 但若以下全部门槛通过，可以认为当前版本已达到“可上线”的工程标准

## 4. 测试环境要求

### 4.1 服务组件

- website_aicut API 服务
- scheduler / admin 调度入口
- 至少 2 个可注册的 `smart_cut_worker`
- 真实 TOS bucket
- 可访问的数据库

### 4.2 Worker 环境

- 使用真实镜像：`website_aicut-smart_cut_worker:latest`
- Worker 能声明支持：
  - `smart_cut_analyze`
  - `smart_cut_preview`
  - `smart_cut_finalize`
- 容器工作目录可写：`/data/smart-cut`
- 容器具备访问 TOS、ffmpeg、ffprobe、aicut2602 的能力

### 4.3 测试数据准备

至少准备 3 套真实数据：

#### Case A：标准短视频
- 时长：30 秒到 90 秒
- 分辨率：常见竖屏或横屏
- 文案匹配度较高
- 用途：验证标准主流程

#### Case B：中等复杂视频
- 时长：2 分钟到 5 分钟
- 存在较多停顿
- 需要至少 2 次 preview 调整
- 用途：验证多次 preview 与最终收敛

#### Case C：大文件/长视频
- 时长：8 分钟以上或体积明显更大
- 用途：验证真实性能、长耗时、上传稳定性

### 4.4 TOS 路径规范

每次测试必须使用独立前缀：

```text
smart-cut-e2e/{run_id}/{task_id}/...
```

避免历史数据污染结果。

## 5. 测试分层

上线前必须完成 4 层验证：

1. 自动化规则层
2. Fake TOS 集成层
3. 真实数据主流程层
4. 真实数据故障恢复层

其中第 3、4 层是本文重点。

## 7. 真实数据主流程测试

## P0-E2E-001：创建任务并完成输入绑定
- 目标：验证真实输入数据可通过 TOS 正确绑定到任务
- 前置条件：
  - 已启动 API
  - 已准备真实视频和标准文案
- 操作步骤：
  1. 创建 smart-cut 任务
  2. 调用 `upload-prepare`
  3. 将视频和文案直传 TOS
  4. 调用 `upload-complete`
- 预期结果：
  - 任务状态进入可分析状态
  - 数据库中记录 `original_video_tos_key` 与 `reference_text_tos_key`
  - TOS 对象真实存在
- 关键断言：
  - key 前缀属于当前任务
  - 不接受任意外部 URL

## P0-E2E-002：analyze 主流程成功
- 目标：验证 analyze 任务可在真实 Worker 上成功执行
- 前置条件：
  - `upload-complete` 成功
  - 至少 1 个 analyze 兼容 Worker 在线
- 操作步骤：
  1. 调度 analyze
  2. Worker 接单
  3. Worker 从 TOS 下载输入
  4. Worker 执行 analyze
  5. Worker 回写产物和状态
- 预期结果：
  - 业务任务进入 `waiting_user`
  - 调度任务完成
  - Worker 释放回空闲
- 关键断言：
  - analyze 关键产物存在
  - `script` 可从任务详情获取
  - analyze 后 Worker 不继续占用任务

## P0-E2E-003：preview 主流程成功
- 目标：验证 preview 可正确产生试听结果
- 前置条件：
  - analyze 已成功
  - 用户提交合法 `edited_script`
- 操作步骤：
  1. 发起 preview
  2. Worker 接单
  3. Worker 下载所需输入/复用缓存
  4. Worker 执行 preview
  5. Worker 上传 `audio_b.mp3`
- 预期结果：
  - preview 成功
  - 任务重新回到可等待用户状态
  - Worker 释放
- 关键断言：
  - `audio_b_tos_key` 已回写
  - `audio_b_url` 可访问
  - `edited_delay_cuts` 与 `pause_cuts_on_original` 已持久化

## P0-E2E-004：finalize 主流程成功
- 目标：验证 finalize 可在真实数据上生成最终视频
- 前置条件：
  - 至少有 1 次成功 preview
- 操作步骤：
  1. 发起 finalize
  2. Worker 接单
  3. Worker 下载 finalize 所需输入
  4. Worker 生成 `final_video.mp4`
  5. Worker 上传到 TOS
- 预期结果：
  - 业务任务进入成功状态
  - 返回 `final_video_url`
  - Worker 释放
- 关键断言：
  - `final_video.mp4` 在 TOS 真实存在
  - 下载链接可访问
  - 文件大小大于 0

## P1-E2E-005：GroundTruth 成功上传
- 目标：验证 `feed_to_ai=true` 时 GroundTruth 目录成功落 TOS
- 前置条件：
  - finalize 请求中 `feed_to_ai=true`
- 操作步骤：
  1. 发起 finalize
  2. 等待任务完成
  3. 检查 GroundTruth 路径
- 预期结果：
  - `groundtruth_tos_key` 已写回
  - TOS 目录包含必要文件
- 关键断言：
  - `reference.txt`
  - `analyze_script.txt`
  - `edited_script.txt`
  - `asr_result.json`
  - `metadata.json`

## P1-E2E-006：vertical_1080p 模式成功
- 目标：验证竖屏归一化链路在真实视频上可用
- 前置条件：
  - preview 成功
- 操作步骤：
  1. 用 `output_mode=vertical_1080p` 发起 finalize
  2. 等待任务成功
- 预期结果：
  - 最终视频生成成功
  - normalize 相关文件生成
- 关键断言：
  - `normalized_input.mp4` 或其上传记录存在
  - `normalized_input.process.json` 存在

## P1-E2E-007：preview 可重复执行两次并以最后一次为准
- 目标：验证多次试听时数据收敛正确
- 前置条件：
  - analyze 成功
- 操作步骤：
  1. 发起 preview #1
  2. 发起 preview #2
  3. 发起 finalize
- 预期结果：
  - finalize 使用最后一次成功 preview 的产物
- 关键断言：
  - `finalize_source_edit_id == active_edit_id`
  - 不使用旧 preview 的 cuts

## P1-E2E-008：长视频 Case C 真实跑通
- 目标：验证长耗时和较大输入下的真实稳定性
- 前置条件：
  - Case C 素材已准备
- 操作步骤：
  1. 按主流程完成 analyze -> preview -> finalize
- 预期结果：
  - 全链路成功
- 关键断言：
  - 无异常退出
  - Worker 不因时长过长而漏状态
  - 最终视频与 TOS 上传正常

## 8. 真实数据恢复与重派测试

## P0-REC-001：analyze 完成后 Worker 释放
- 目标：验证分步骤任务不会长期占住 Worker
- 操作步骤：
  1. 完成 analyze
  2. 观察设备状态
- 预期结果：
  - Worker 回到 `idle`
  - 业务任务处于等待用户阶段

## P0-REC-002：preview 可由新 Worker 接续
- 目标：验证跨 Worker 接续能力
- 前置条件：
  - analyze 已在 Worker-A 完成
  - Worker-B 在线
- 操作步骤：
  1. 停止或下线 Worker-A
  2. 发起 preview
  3. 由 Worker-B 接单执行
- 预期结果：
  - preview 成功
- 关键断言：
  - Worker-B 可从 TOS 获取所需输入
  - 不依赖 Worker-A 本地缓存

## P0-REC-003：finalize 可由不同 Worker 接续
- 目标：验证最终剪辑不依赖 preview 所在机器
- 前置条件：
  - preview 成功
  - 更换 Worker
- 操作步骤：
  1. 下线 preview 执行机器
  2. 发起 finalize
- 预期结果：
  - finalize 成功
- 关键断言：
  - finalize 所需中间产物已持久化

## P1-REC-004：任务 suspended 后 72 小时内恢复成功
- 目标：验证业务恢复入口
- 操作步骤：
  1. 任务进入 `suspended`
  2. 在保留期内发起恢复
- 预期结果：
  - 恢复原任务
  - 不创建新任务

## P0-REC-005：超时后不可恢复
- 目标：验证过期保护
- 操作步骤：
  1. 将任务推进到超时关闭
  2. 再尝试恢复
- 预期结果：
  - 恢复失败
  - 不出现继续入口

## 9. 真实数据故障测试

## P0-ERR-001：upload-complete 传错 key 被拒绝
- 目标：验证输入绑定安全性
- 操作步骤：
  1. 创建任务 A
  2. 用任务 B 的 key 调用任务 A 的 `upload-complete`
- 预期结果：
  - 后端拒绝绑定

## P0-ERR-002：TOS 中对象不存在时 upload-complete 失败
- 目标：验证对象存在性校验
- 操作步骤：
  1. 构造不存在的 key
  2. 调用 `upload-complete`
- 预期结果：
  - 后端拒绝

## P0-ERR-003：analyze 执行中 Worker 异常退出
- 目标：验证运行中断可见性
- 操作步骤：
  1. 发起 analyze
  2. Worker 进入运行中后强制停止容器
- 预期结果：
  - 不得误标成功
  - 系统出现失败或报警

## P0-ERR-004：preview 本地成功但 audio_b 上传失败
- 目标：验证 preview 上传失败不会被误判成功
- 操作步骤：
  1. 在 preview 上传阶段模拟 TOS 失败
- 预期结果：
  - 任务进入 `preview_upload_failed` 或等价失败状态
  - 不返回可用的试听 URL

## P0-ERR-005：finalize 本地成功但 final_video 上传失败
- 目标：验证最终上传失败不会被误判成功
- 操作步骤：
  1. 在 final 视频上传阶段模拟 TOS 失败
- 预期结果：
  - 任务进入 `final_upload_failed` 或等价失败状态
  - 不得标记为成功

## P1-ERR-006：GroundTruth 上传失败不阻塞最终视频成功
- 目标：验证非阻断后处理策略
- 操作步骤：
  1. 让最终视频上传成功
  2. 让 GroundTruth 上传失败
- 预期结果：
  - 最终视频任务仍可成功
  - GroundTruth 状态单独标记失败

## P1-ERR-007：preview 输入不合法被拒绝
- 目标：验证编辑协议安全性
- 操作步骤：
  1. 提交包含正文字符改写的 `edited_script`
- 预期结果：
  - preview 被拒绝
  - 不产生新 preview 产物

## P1-ERR-008：重复点击 preview / finalize 不产生并发分叉
- 目标：验证接口幂等性
- 操作步骤：
  1. 用户快速重复点击 preview
  2. 用户快速重复点击 finalize
- 预期结果：
  - 不产生重复调度分支
  - 同一任务不会并发执行两次同阶段任务
